# Ponytail audit — artflow-studio/table (G:\Web Development\appRepositories\Packages\table) — 2026-09-17

Independent pass, done after skimming the existing `AUDIT.md` (1.5.6 → 1.6.0: 27 traits → 11 "concerns", 30,459 → 8,700 lines) for context only. That pass fixed correctness bugs and cut whole *unreachable trait files*. It did not check whether the 11 surviving concerns still carry dead methods inside them — most of the findings below are exactly that: methods and properties with zero live callers, left over inside files that otherwise look purposeful. Reachability was checked by grepping every candidate method/property name across `src/`, `resources/`, `tests/`, `config/`, `docs/`, `README.md` and excluding the defining file, then re-checking any internal call chain by hand. Scope is over-engineering/complexity only, per instructions — no correctness/security/performance findings, even where obviously present.

Zero callers anywhere in `src/`, `resources/`, `tests/`, or `docs/` — the real cell rendering path is `AftableComponent::renderRawHtml()`, which compiles actual Blade. Only `extractJsonValue()` + `getNestedValue()` (~46 of 551 lines) are reachable, via `AftableComponent::exportCellValue()` and the Blade template's JSON-column branch. Delete everything else. [src/Concerns/RendersCells.php]
2. `delete:` `src/Concerns/ValidatesInput.php` — a hand-rolled Laravel-Validator clone (`applyValidationRule` reimplements `required`/`string`/`numeric`/`integer`/`email`/`url`/`date`/`min`/`max`/`in`/`unique`) plus a permissions/action-authorization layer (`validateAction`, `userCanPerformAction`, `userHasPermission` — hardcoded `return true; // to avoid breaking existing functionality`, `validateActionRequirement(s)`, `validateActionBusinessLogic`, `isActionValid`, `getActionConfig`) plus `getColumnConfig`/`isColumnValid`/`validateColumn`/`validateRelationColumns`/`relationExists`/`getRelationType`/`getCurrentStatus`/`isValueUnique`/`sanitizeFilterValue`/`sanitizeHtmlContent`/`sanitizeUtilitySearch`/`generateBasicCacheKey`/`validateExportFormat`/`validateJsonPath`. None of these has a live caller — `getColumnConfig`'s only call site is inside the also-dead `RendersCells::renderCellValue()`; `validateJsonPath`'s only call site is inside the also-dead `SortsRows::applySortByJson()`; `validateRelationColumns()` even calls `$this->parseRelationString()` expecting a `['valid' => ...]` shape that method doesn't return, proof nothing ever runs it. ~450 of 687 lines are this dead cluster. Keep `isValidColumn()`, `validateRelationString()`, `validateSortDirection()` — genuinely used. [src/Concerns/ValidatesInput.php]

The real row/bulk actions the shipped Blade template renders are plain `route()` links/forms (see the template's `@foreach ($actions as ...)` block) — this trait's only reachable entry point, `handleBulkAction()`, is allow-listed in `GuardsActions` but not bound to anything in the shipped UI. ~420 of 445 lines. Keep `clearSelectedRows()` and `refreshComponent()` — both have real callers elsewhere on the component. [src/Concerns/HandlesActions.php]
